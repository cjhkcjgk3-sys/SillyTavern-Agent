## 三大产品发展方向

- **模型能力充分释放**：完善 API 适配、多模态支持、工具调用、模型能力配置和请求诊断；减少固定模型白名单及不必要的调用限制。
- **智能体运行框架**：自主执行循环、动态子智能体、并行任务、自动上下文压缩、技能、MCP、任务状态及恢复。
- **创作工作环境**：世界书及角色卡工作区、主动检索、实时修改、差异与回滚、预设和人机协作。

## 功能协作关系

| 组成部分 | 职责 |
| --- | --- |
| 用户 | 提供目标、意见、关键创作决策和权限 |
| 预设 | 固定工作指令、整体工作方式 |
| Skills | 按需加载的专项工作方法 |
| 模型 | 思考、规划、决策、创作、审查 |
| Harness | 维持执行循环，管理任务、上下文、工具与资源 |
| 子智能体 | 按主智能体的任务分配执行专项工作 |
| 工具系统 | 将模型的决策转化为实际操作，反馈执行结果 |
| 工作区 | 保存世界书、角色卡、正式成果及相关资料 |
| 上下文管理 | 保留工作记忆、自动压缩、按需恢复原始记录 |
| 变更管理 | 记录操作、验证修改、对比差异、恢复历史内容 |
| 权限与资源管理 | 控制授权、成本、预算、异常和停止条件 |

## 工作闭环

用户提供目标 → 智能体理解、规划和读取资料 → 自主执行、调用工具或调度子智能体 → 更新工作区并验证结果 → 检查关联影响并修正 → 完成任务或继续下一轮。

在执行期间，用户可随时干预；必要时智能体主动暂停并请求用户决策。自动上下文管理维持长期工作所需的信息，任务状态与修改记录支持恢复。

## 项目基础与规划边界

- 基于 SillyTavern 的分叉项目，保留原有聊天、角色扮演、世界书、角色卡、预设、扩展生态和使用习惯。
- 普通聊天模式与智能体工作模式并存。
- 已有[世界书协作工作台](https://github.com/cjhkcjgk3-sys/sillytavern-worldbook-workbench)是世界书读写、审批及回滚功能的参考与潜在复用来源；实际复用范围待技术评估。
- 目标覆盖电脑、服务器及 Android；SillyDroid 可作为后续移动端适配参考。
- 现阶段仅确定理想产品和功能设想，具体实现、技术可行性、优先级和开发成本另行规划。

**核心原则：框架提供能力，模型决定如何使用能力；以实际成果交付为目标，尽可能复用已有功能，保持简单易用。**
