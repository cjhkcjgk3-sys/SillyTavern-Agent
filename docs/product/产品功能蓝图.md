# SillyTavern Agent Harness
## 酒馆智能体运行框架 · 产品功能蓝图 V1.0

本文确定产品定位、功能要求、使用体验和预期效果，暂不确定技术选型、代码架构、接口设计及具体实现方式。各项功能属于产品设想，尚未确定开发优先级。

整体功能总览见[整体功能总览](功能总览.md)。

# 一、产品定位

以开源软件 SillyTavern 为基础进行衍生开发，在保留酒馆原有功能、使用习惯及扩展生态的基础上，赋予 AI 模型完整的智能体工作环境。

充分释放模型自身具备的智能、推理、多模态、工具调用、任务规划和自主决策能力，使酒馆从以对话和文本生成为主的交互平台，发展为能够自主开展工作、持续推进任务并交付实际成果的通用智能体平台。

主要应用方向包括：

- 世界观构建与复杂设定创作。
- 人物塑造与角色卡编写。
- 小说创作与剧情设计。
- 创意思路探索与头脑风暴。
- 设定审查与逻辑一致性检查。
- 资料检索、整理与研究。
- 传统角色扮演与日常聊天。
- 其他适合通过智能体完成的任务。

底层能力保持通用性，具体工作方向由用户指令、预设、技能及工作区决定。

# 二、核心设计原则

## 2.1 充分释放模型能力

凡是模型及其 API 已经具备的能力，软件应尽可能提供相应的使用途径。

减少过时的模型识别规则、固定白名单、不必要的调用限制及功能限制对模型能力的影响。

## 2.2 模型主导，框架辅助

模型负责理解任务、分析问题、制定计划、选择工具、分配工作、作出判断及整合成果。

运行框架负责提供工具、维持执行循环、管理上下文、保存工作状态、控制权限及资源、验证操作结果。

充分发挥模型自主决策能力，避免将智能体的工作方式固化为僵硬的预定流程。

## 2.3 成果交付优先

模型应能够直接操作工作区，将实际工作成果保存至对应位置。

例如，完成世界观修改后直接更新世界书，而不是仅在聊天窗口输出修改后的文字，再由用户手动复制整理。

## 2.4 简单易用

保留酒馆原有操作习惯和界面风格。

功能与交互设计遵循必要、实用、精简的原则。能够复用的功能优先复用，能够通过统一入口完成的操作不重复设置入口。

复杂能力应当服务于更加简单的用户体验。

## 2.5 原有生态兼容

尽可能保留 SillyTavern 原有的角色卡、世界书、预设、正则、脚本、插件、聊天记录及模型连接功能。

支持电脑端、服务器部署及 Android 手机端使用，保持核心功能和使用体验的一致性。

# 三、工作模式

提供普通聊天模式和智能体工作模式。

## 3.1 普通聊天模式

保留酒馆原有的聊天、角色扮演、文本生成及相关功能。

用户可以按照原有方式使用酒馆，也可以根据需要使用世界书读写等已授权的工具能力。

## 3.2 智能体工作模式

用户提供任务目标后，模型能够自主规划、持续执行、调用工具、检查成果及解决问题，直到任务完成或需要用户介入。

适用于复杂创作、设定修改、资料研究及其他多步骤任务。

两种模式能够根据实际需求进行切换，切换时妥善保留已有任务状态及工作成果。

# 四、智能体自主运行系统

## 4.1 持续执行能力

模型能够在一次 API 请求结束后，自主进入下一轮工作。

根据前一轮的工作成果、工具返回结果、新发现的问题及当前任务状态，决定后续工作内容。

支持连续执行：

- 分析问题与制定计划。
- 自主提出问题并解决问题。
- 探索新的创作思路。
- 调用工具完成实际操作。
- 根据执行结果调整后续工作。
- 发现并解决关联问题。
- 检查和修正已有成果。
- 整合成果并完成任务交付。

持续执行不受单次模型输出长度限制，能够跨越多轮模型调用完成长时间、复杂的工作。

## 4.2 自主规划能力

模型根据任务复杂程度，自主决定是否需要制定工作计划。

能够拆解任务、确定优先级、安排执行顺序，并根据新发现的信息动态调整计划。

简单任务可以直接执行，复杂任务可以进行阶段性规划。

## 4.3 自主探索能力

模型能够根据现有成果，进一步推导潜在问题、关联影响和有价值的创意。

例如，建立力量体系后，自主分析该体系对文明历史、社会结构、宗教、经济、军事及人物设定的影响。

探索范围围绕用户目标展开，发现的问题能够继续处理，并最终收敛为实际成果。

## 4.4 自主审查能力

模型能够主动检查自己的工作成果，包括：

- 是否满足用户要求。
- 是否存在内容遗漏。
- 是否存在逻辑冲突。
- 是否影响其他关联设定。
- 修改是否真正生效。
- 是否产生新的问题。
- 整体成果是否具备一致性和完整性。

发现问题后自主修正，必要时重新审查。

## 4.5 工作终止与暂停

模型能够根据实际情况判断工作状态：

- 继续执行。
- 等待工具或子智能体返回结果。
- 等待用户提供必要信息。
- 等待用户作出决策或批准操作。
- 遇到无法自行解决的问题。
- 达到资源预算或其他运行限制。
- 完成任务。

任务完成后主动停止，并汇报实际工作成果。

# 五、任务管理系统

## 5.1 任务状态管理

持续记录当前任务的必要信息，包括：

- 用户的原始目标及最新要求。
- 当前工作计划。
- 已完成的工作。
- 正在处理的工作。
- 尚未完成的事项。
- 已发现的问题。
- 已确定的设计决策。
- 待用户确认的事项。
- 已产生的工作成果。

任务状态与聊天记录相互关联，能够在长时间工作和上下文压缩后继续保持。

## 5.2 任务持久化

保存任务进度及必要的工作状态。

关闭页面、重新进入酒馆、切换设备或发生运行中断后，在相应数据可用的情况下能够恢复任务。

已经完成的工作不需要无意义地重复执行。

## 5.3 后台工作

智能体能够在运行环境保持可用的情况下持续执行任务，无须用户始终停留在当前聊天页面。

用户可以查看任务运行状态、阶段成果和当前进度。

## 5.4 用户实时干预

用户可以在智能体运行过程中：

- 补充意见和要求。
- 调整工作方向。
- 修改任务目标。
- 暂停、恢复或终止任务。
- 回答智能体提出的问题。
- 批准或拒绝相关操作。

智能体应及时吸收用户的新要求，并调整后续工作计划及受影响的已有成果。

# 六、子智能体系统

## 6.1 动态创建子智能体

主智能体能够根据任务需要，自主创建子智能体并分配工作。

子智能体的职责、数量、任务内容及工作范围由主智能体根据实际情况决定。

例如：

- 世界观设计智能体。
- 文明历史研究智能体。
- 人物塑造智能体。
- 资料检索智能体。
- 设定一致性审查智能体。
- 文学质量审查智能体。

以上职责仅为应用示例，子智能体的身份与分工不预先固定。

## 6.2 独立上下文

每个子智能体拥有相对独立的工作上下文。

根据分配的任务获取必要的用户要求、工作区资料、相关设定及工具权限，减少无关信息对工作效率的影响。

## 6.3 并行与协同工作

支持多个子智能体同时执行不同任务，也支持根据任务依赖关系顺序执行。

主智能体能够分配任务、发送补充要求、获取进度、读取成果、调整任务及终止子智能体。

## 6.4 多模型协作

默认可以使用与主智能体相同的模型。

同时支持根据需要为子智能体配置不同模型，利用不同模型在创作、推理、检索、审查等方面的能力差异。

## 6.5 成果整合

主智能体负责检查子智能体的工作成果、解决不同成果之间的分歧，并进行统一整理和交付。

多智能体共同修改工作区时，应避免内容覆盖、重复修改及设定冲突。

## 6.6 资源管理

用户能够控制子智能体的数量、并行规模、权限和资源预算。

子智能体的实际消耗计入整体任务成本。

# 七、世界书工作区

## 7.1 工作区定位

将世界书从主要承担背景信息注入的资料库，扩展为模型能够主动读取、检索、创作和修改的持久化工作区。

世界书、角色卡、创作资料及其他相关内容共同构成项目的工作环境。

## 7.2 工作区范围

用户可以指定一本或多本世界书作为当前任务的工作区。

模型在授权范围内开展工作，支持跨世界书检索和联合修改。

不同创作项目拥有各自对应的工作范围，避免误操作无关资料。

## 7.3 主动读取与检索

模型能够自主执行以下操作：

- 查看世界书及条目目录。
- 搜索标题、关键词和正文内容。
- 读取指定条目的完整内容。
- 分批读取大量设定。
- 查找其他条目中的关联内容。
- 查阅修改记录及历史内容。

主动读取与酒馆原有的关键词激活机制并存。

即使条目未被关键词激活，模型也能够根据当前任务主动查阅。

## 7.4 世界书实时编辑

模型能够在授权范围内：

- 创建世界书及条目。
- 修改条目正文。
- 修改标题与关键词。
- 修改必要的激活规则及条目配置。
- 删除废弃条目。
- 进行局部内容替换。
- 完整重写指定条目。
- 执行批量及跨世界书修改。

修改后的内容应当及时保存，并在后续工作中正确生效。

## 7.5 局部修改与全文重写

支持根据任务需要选择修改方式。

局部修改适用于少量内容调整，保留原有无关内容，减少重复生成及 Token 消耗。

全文重写适用于整体结构调整、设定重构及内容整合。

## 7.6 关联性检查

模型修改某项设定时，能够主动搜索其他相关设定，判断修改产生的影响，并对受影响内容进行同步调整。

例如修改人物经历后，检查相关人物关系、历史事件、剧情记录和世界观设定。

## 7.7 写入验证

世界书修改应具备必要的可靠性保障：

- 修改前读取原始内容。
- 检查内容是否已经发生变化。
- 保存必要的原始版本。
- 保护未要求修改的内容及配置。
- 修改完成后重新读取并验证。
- 保存失败时明确反馈实际状态。

# 八、变更管理与版本恢复

## 8.1 修改记录

记录模型对工作区进行的实际操作，包括：

- 修改对象。
- 修改前后的内容。
- 修改理由。
- 修改时间。
- 所属任务。
- 执行及验证状态。

## 8.2 差异查看

用户能够直观查看内容的新增、删除及修改部分，也能够查看修改前后的完整内容。

## 8.3 修改撤销

支持撤销单次修改及恢复历史内容。

当相关内容已经发生后续变化时，应当识别冲突，避免直接覆盖后续成果。

## 8.4 批量回滚

支持按照任务或关联修改批次进行整体恢复。

涉及多个世界书条目的关联修改，可以统一回滚，保持设定的一致性。

## 8.5 持久化保存

修改记录、历史版本及必要备份应当可靠保存，不因普通页面刷新或浏览器临时数据清理而轻易丢失。

# 九、自动上下文管理

## 9.1 分层管理

将模型工作上下文划分为四个主要层次。

### 固定指令层

包括预设、工作规范、创作要求、权限及必要的用户指令。

保持持续有效，不因普通上下文压缩而丢失。

### 正式成果层

包括世界书、角色卡、已经确立的设定及其他工作区成果。

持久化保存，由模型根据实际任务按需读取。

### 工作记忆层

包括任务状态、关键决策、用户意见、创作思路、重要发现、待解决问题及其他必要的工作经验。

随着任务推进持续更新。

### 近期对话层

包括最近的完整聊天记录、创作讨论及工具执行过程。

根据上下文容量和任务需要进行动态管理。

## 9.2 自动压缩

根据模型上下文容量、实际 Token 使用情况及用户设定，自动判断压缩时机。

压缩旧有对话，保留近期完整上下文及必要的工作记忆，为后续任务腾出空间。

## 9.3 信息保真

压缩应重点保留：

- 用户的重要要求和意见。
- 已经确定的创作方向。
- 有价值的创意与设计思路。
- 设定之间的关联关系。
- 已否决的方案及其原因。
- 已经发现的错误、问题及解决方法。
- 尚未完成的工作。
- 重要事实及约束条件。

压缩篇幅根据原始内容的信息量动态调整，以信息价值和保真程度为优先依据。

## 9.4 原始记录保留

上下文压缩主要改变发送给模型的内容，原始聊天记录仍然保留。

模型能够根据需要重新检索和读取历史记录，恢复压缩过程中省略的细节。

## 9.5 成果与记忆协同

已经保存至世界书的正式设定，可以通过条目引用和必要摘要参与工作记忆管理。

减少在正式成果、聊天历史和压缩记忆中反复保存及发送相同内容。

# 十、预设与技能系统

## 10.1 预设系统

保留酒馆原有预设功能，并赋予预设智能体固定工作指令的职责。

预设可以定义：

- 模型身份与职责。
- 创作原则及风格。
- 工作方式。
- 自主决策范围。
- 工具使用要求。
- 审查及完成标准。
- 与用户的协作方式。

用户可以通过切换预设改变智能体的整体工作方向。

## 10.2 技能系统

支持独立的专项技能库。

技能用于保存特定任务的工作方法、流程、知识、规范及参考资料。

例如：

- 角色卡编写技能。
- 世界观设计技能。
- 设定一致性审查技能。
- 上下文总结技能。
- 文学创作技能。
- 防御性表达优化技能。
- 资料研究技能。

## 10.3 技能管理与调用

支持用户创建、导入、编辑、启用及管理技能。

模型能够根据当前任务识别并主动加载相关技能。

预设负责整体工作规则，技能负责具体工作方法。两者协同发挥作用。

技能按需加载，减少无关提示词占用上下文空间。

# 十一、统一工具系统

## 11.1 工具调用

模型能够自主发现、选择及调用当前任务可用的工具，并根据返回结果决定后续行为。

支持连续工具调用及任务需要的并行工具调用。

## 11.2 内置工具类别

### 工作区工具

世界书、角色卡、创作资料及相关内容的读取、检索、创建和修改。

### 检索工具

联网搜索、聊天历史检索、资料查询及内容定位。

### 智能体工具

创建、调度、管理子智能体并获取工作成果。

### 任务工具

制定计划、更新任务进度、记录问题及管理任务状态。

### 上下文工具

压缩上下文、读取历史记录及恢复必要信息。

### 交互工具

向用户提出问题、请求决策及申请操作权限。

### 验证工具

检查实际操作结果、查看内容差异及验证工作成果。

## 11.3 MCP 与外部工具

支持接入 MCP 服务及其他外部工具接口，扩展智能体的实际操作能力。

用户能够管理工具来源、启用状态及授权范围。

## 11.4 插件能力协同

现有酒馆插件提供的适用能力，应当尽可能能够被智能体发现和调用。

支持持续扩展工具体系，使新增能力能够参与智能体工作流程。

# 十二、模型能力与 API 管理

## 12.1 多模型支持

保留并完善酒馆原有的模型及 API 渠道支持能力。

支持主流模型厂商、官方 API、Google Vertex AI、OpenAI 兼容接口及其他适用渠道。

## 12.2 模型能力配置

对不同模型及 API 渠道所具备的能力进行独立管理，包括：

- 文本输入与输出。
- 图片识别。
- 视频识别。
- 音频识别。
- 文件及其他多模态输入。
- 多模态输出。
- 深度思考及思考等级。
- 联网搜索。
- 原生函数调用。
- 并行工具调用。
- 上下文容量。
- 最大输出长度。
- 上下文缓存。
- 结构化输出。
- 其他新增模型能力。

## 12.3 能力识别与手动配置

支持读取服务商提供的模型能力信息、使用已有配置及进行必要的能力测试。

用户能够手动调整模型能力配置。

新模型或自定义模型名称能够根据实际能力使用相应功能，减少固定模型白名单造成的限制。

## 12.4 独立更新

模型名称、能力配置及相关参数应当能够独立于软件整体版本进行更新。

当 API 请求协议及响应格式发生变化时，能够针对相应接口进行适配。

## 12.5 功能兼容性

正确处理不同模型、API 渠道及功能组合之间的兼容关系。

尽可能支持多模态、深度思考、联网搜索和工具调用的联合使用。

当服务商确实不支持某项功能或功能组合时，准确说明限制来源。

## 12.6 输出连续性

正确识别模型正常完成、输出达到上限、连接中断及异常终止等情况。

根据任务状态和实际情况恢复生成、继续工作或提示用户，减少长篇创作中的意外截断及内容丢失。

# 十三、请求诊断与运行可观测性

## 13.1 请求诊断

用户能够查看模型调用的必要信息，包括：

- 实际使用的模型及 API 渠道。
- 实际发送的请求参数。
- 发送的上下文及提示词。
- 图片、文件及其他多模态内容的发送状态。
- 已发送的工具定义。
- 请求过程中被转换或过滤的内容。
- 服务商返回的结果及错误信息。
- 模型停止生成的原因。

敏感密钥及认证信息应当自动隐藏。

## 13.2 工具调用记录

能够查看模型调用了哪些工具、调用参数、执行结果及失败原因。

## 13.3 智能体运行状态

用户能够查看：

- 当前任务状态。
- 当前工作进度。
- 已进行的模型调用。
- 子智能体运行情况。
- 已完成的实际操作。
- 正在等待的事项。
- 异常及中断原因。

相关信息以清晰、简洁的方式呈现，详细记录可以按需展开。

# 十四、权限与安全管理

## 14.1 工作权限模式

提供三个基本工作权限模式。

### 讨论模式

模型可以读取授权资料、讨论问题及提出修改建议。

### 审批模式

模型能够提出实际修改方案，经用户确认后执行。

### 自主模式

模型可以根据任务目标，在授权范围内自主执行修改及其他操作。

## 14.2 授权范围

用户能够控制智能体可访问的工作区、可使用的工具及可执行的操作。

主智能体为子智能体分配的权限应当处于用户允许的范围之内。

## 14.3 关键决策确认

涉及创作核心方向、重大设定取舍、超出授权范围的操作及其他必须由用户决定的问题时，模型能够主动询问用户。

常规工作由智能体自主处理，减少不必要的确认操作。

## 14.4 数据保护

对工作区内容、任务状态、历史记录、模型密钥及其他敏感信息进行妥善管理。

具备必要的数据备份、恢复及操作冲突处理能力。

# 十五、Token 与资源管理

## 15.1 消耗统计

统计当前任务及各模型、子智能体的资源消耗，包括：

- 输入 Token。
- 输出 Token。
- 服务商返回的思考 Token。
- 缓存相关 Token。
- 模型调用次数。
- 任务运行时间。
- API 费用或基于价格配置计算的估算费用。

## 15.2 预算控制

用户能够设置任务资源限制，包括：

- 最大 Token 消耗。
- 最大调用次数。
- 最大运行时间。
- 子智能体数量及并行规模。
- 最大费用预算。

达到限制时，根据实际情况暂停工作、保存进度并通知用户。

## 15.3 消耗优化

通过按需读取工作区、自动压缩上下文、局部修改、按需加载技能、利用模型缓存及合理分配子智能体上下文等方式，减少不必要的资源消耗。

在保证工作质量的前提下，提高实际成果与 Token 消耗之间的效率。

## 15.4 异常处理与恢复

妥善处理网络中断、API 限流、服务异常、工具失败、内容保存失败及其他运行异常。

保留已经完成的工作，并根据实际情况重试、调整计划、暂停或恢复任务。

避免无意义重复调用、无限重试及重复执行已完成的操作。

# 十六、用户交互与使用体验

## 16.1 统一交互入口

以酒馆原有聊天界面作为主要的人机交互窗口。

用户能够通过自然语言分配任务、提供意见、操作工作区及调整工作方向。

## 16.2 工作区可视化

用户能够方便地查看当前工作区、世界书条目、修改状态、历史版本及待确认内容。

## 16.3 任务可视化

能够直观查看当前工作进度、任务计划、子智能体状态、工具调用及资源消耗。

## 16.4 交互精简

优先复用原有界面组件、设置入口及通用操作。

相关功能统一管理，避免功能增加导致界面及操作方式过度复杂。

## 16.5 移动端适配

手机端应当能够完整使用智能体工作模式、世界书操作、任务管理、权限审批及资源查看等核心能力。

保持操作便捷、内容清晰和交互一致性。

# 十七、原生功能与扩展生态

保留并充分利用酒馆原有的：

- 聊天及消息管理。
- 角色卡与角色扮演系统。
- 世界书及关键词激活系统。
- 预设与提示词管理。
- 正则表达式。
- 脚本与扩展系统。
- 模型及 API 连接。
- 多模态交互。
- 聊天记录及数据导入导出。
- 已有用户设置及使用习惯。

新增能力与原生功能应当相互协作，共同构成完整的智能体工作环境。

# 十八、整体功能协作关系

用户负责提供目标、意见和关键创作决策。

预设负责定义智能体的整体工作方式。

技能负责提供专项工作方法。

模型负责思考、规划、决策及创作。

Harness 负责维持持续运行、管理任务状态、协调工具及资源。

子智能体负责承担主智能体分配的专项工作。

工具系统负责将模型的决策转化为实际操作。

世界书工作区负责保存正式创作成果及相关资料。

上下文管理系统负责维持长期工作的记忆及信息连续性。

变更管理系统负责保存操作记录、验证修改及恢复历史内容。

权限和资源管理系统负责维持工作的可控性。

以上能力共同形成从用户提出目标，到智能体自主执行、检查、修正及交付成果的完整工作闭环。

# 十九、最终产品目标

用户只需提供任务目标、必要的创作要求及工作权限，智能体即可根据实际需要：

1. 理解任务并读取相关资料。
2. 自主制定工作计划。
3. 探索创意及解决问题。
4. 调用工具开展实际工作。
5. 创建并调度子智能体。
6. 实时修改世界书及其他工作区内容。
7. 检查修改产生的关联影响。
8. 自动管理上下文及工作记忆。
9. 在必要时与用户交流并获取决策。
10. 持续审查、修正及完善成果。
11. 完成任务并保存实际成果。
12. 向用户汇报工作结果、修改内容及未解决事项。

最终形成一个以模型智能为核心、以 Harness 为运行基础、以世界书为主要创作工作区、以酒馆为人机交互平台的通用智能体工作环境。

使模型能够自主、持续、完整地完成用户交付的工作，并最大程度发挥其实际能力。
