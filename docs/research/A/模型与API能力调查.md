## 能力独立更新与诊断的可行性

能力描述宜保留渠道、API 协议、endpoint/地区、模型 ID 或部署名、证据日期、来源和覆盖范围。把输入/输出模态、Schema、工具、并行、搜索、思考等级、上下文/输出限制和缓存记录为独立字段，同时存显式组合约束。服务商元数据、本地注册表、用户覆盖和微型探针要能追溯。覆盖只改变酒馆选择，服务商最终拒绝仍应报告。协议修改与配置数据更新可独立发布，但请求/响应契约变化仍需要适配器改动及回归。

关键诊断应对照「选定模型与前端组装 → 后端出站 → 原始响应分类 → 用户看到的状态」。记录过滤阶段和原因、媒体 MIME/字节量、发送工具名、停止分类、usage 来源和关联 ID。请求参数/提示词全文按权限按需查看。密钥、Authorization、签名、带 key 查询参数与私有附件应最小暴露。复用 Model List、Prompt Manager 及事件入口，可补最终出站和归一收尾。

Vertex 复现与测试扩展见 T05 和 T13。真实实验应记录项目模式、region、模型 ID、每个组合的最小合成输入、返回 status/finish/usage、是否有签名往返、试验上限。配额或服务异常时记录原始分类、重试次数与可能重复计费。任务写入先核对是否落盘，消耗估算不作为账单。
